# 毎日の作業の流れ

1 つのタスクを、次の 7 つの手順で進めます。

```
① main を最新にする → ② ブランチを作る → ③ Unity で作業する
→ ④ コミットする → ⑤ Push する → ⑥ プルリクエストを出す → ⑦ 仲間が見て、マージする
```

## 言葉の意味

| 言葉 | 意味 |
|---|---|
| リポジトリ | チームのファイルが全部入った箱。GitHub に置いてある |
| main | チームの「完成品」が入っているブランチ。いつでも遊べる状態にしておく |
| ブランチ | 自分の作業用のコピー。ほかの人の作業とまざらない |
| コミット | 「ここまでできた」というセーブポイント |
| Push（プッシュ） | 自分の PC のコミットを、GitHub に送ること |
| Pull（プル） | GitHub にある新しい変更を、自分の PC に持ってくること |
| プルリクエスト（プルリク・PR） | 「自分のブランチを main に入れてください」というお願い |
| マージ | ブランチの変更を main に入れること |
| コンフリクト | 2 人が同じ所を変えて、どちらを使うか Git が決められない状態 |

## ① main を最新にする

1. Unity で保存する（Windows は Ctrl+S、Mac は ⌘+S）
2. GitHub Desktop の上の「Current Branch」が **main** になっているか見る
3. 「Fetch origin」を押す。「Pull origin」に変わったら、それも押す

## ② ブランチを作る

1. 「Current Branch」→「New Branch」
2. 名前を入れて「Create Branch」
   - 名前の付け方：`自分の名前/やること`（英語の小文字とハイフン）
   - 例：`taro/player-jump`、`hanako/title-screen`
3. Notion のタスクの「状態」を「作業中」にして、「ブランチ名」の欄に書く

## ③ Unity で作業する

- 1 つのブランチでは、1 つのタスクだけをやります。
- 1〜3 日で終わるくらいの大きさに分けます。大きいタスクは、Notion で分けましょう。
- ほかの人が持っているシーンは、開いて保存しないでください（くわしくは [チームの決まり](03-team-rules.md)）。

## ④ コミットする

1. Unity で保存する
2. GitHub Desktop の左側で、変わったファイルを見る
   - 変えたつもりのないファイルがあったら、チェックを外します。わからない時は聞きましょう。
   - 新しく作ったファイルは、同じ名前の `.meta` ファイルも必ず一緒に入れます。
3. 左下の「Summary」に、何をしたかを書く
   - 良い例：「プレイヤーがジャンプできるようにした」
   - 悪い例：「修正」「あ」「いろいろ」
4. 「Commit to （ブランチ名）」を押す

コミットは、こまめにして大丈夫です。その日の作業が終わったら、必ずコミットしましょう。

## ⑤ Push する

- そのブランチで初めての時は「Publish branch」、2 回目からは「Push origin」を押します。
- Push すると、GitHub にも保存されます。PC が壊れても、作業は消えません。

## ⑥ プルリクエストを出す

タスクが終わったら出します。

1. GitHub Desktop で「Create Pull Request」を押す（「Preview Pull Request」と出ている時は、それを押してから「Create pull request」）
2. ブラウザで GitHub が開く
3. 上が `base: main` ← `compare: 自分のブランチ` になっているか見る
4. タイトルと説明を書く（説明には、書く所が用意してあります）
5. 右の「Reviewers」で、見てもらう仲間を 1 人選ぶ
6. 「Create pull request」を押す
7. Notion のタスクを「レビュー待ち」にして、「プルリク」の欄に URL を貼る

## ⑦ 仲間が見て、マージする

### 見る人（レビューする人）がやること

1. 説明を読む
2. 「Files changed」のタブで、変わったファイルを見る
   - `.unity` や `.prefab` の中身は読めなくて大丈夫です。
3. できれば、GitHub Desktop でそのブランチに切り替えて、Unity で遊んで確かめる
4. 問題がなければ「Review changes」→「Approve」→「Submit review」
   - 直してほしい所があれば、コメントで伝えます。良かった所も 1 つ書きましょう。

### 出した人がやること

1. Approve をもらったら「Merge pull request」→「Confirm merge」
2. 「Delete branch」を押す（GitHub のブランチを消します。中身は main に入っているので、消えません）
3. Notion のタスクを「完了」にする
4. GitHub Desktop で main に切り替えて「Pull origin」
5. 次のタスクは、また ① から始める（新しいブランチを作る）

## 作業中に、main が新しくなった時

ほかの人のプルリクがマージされたら、自分のブランチにも取り込んでおきましょう。あとでぶつかりにくくなります。

1. Unity で保存して、自分のブランチでコミットしておく
2. 「Fetch origin」を押す
3. 上のメニューの「Branch」→「Update from main」
4. 「Push origin」

コンフリクトが出たら → [困った時](04-trouble.md)
