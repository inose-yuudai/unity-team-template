# チームの決まり

最初に、チーム全員で読みましょう。変えたい決まりがあれば、話し合って書き換えて大丈夫です。

## いちばん大事な 3 つ

1. **main に直接コミットしない**（ブランチを作り、プルリクエストで入れる）
2. **同じシーンを 2 人で同時に触らない**
3. **Unity のバージョンを全員そろえる**

## Unity でぶつからないために

Unity のシーン（`.unity`）やプレハブ（`.prefab`）を 2 人が同時に変えると、Git でうまく合わせられないことが多いです。次のことを守りましょう。

- シーンごとに「持ち主」を決める。持ち主でない人が触る時は、先に声をかける
  - Notion のタスクの「触るシーン」の欄に書いておくと、ぶつかる前に気づけます。
- 自分の作業は、自分用のテストシーン（例：`Assets/Scenes/Test/Taro.unity`）で進める。できた物はプレハブにする
- 本番のシーンには、できたプレハブを置くだけにする
- ファイルを消す・名前を変える・移動する時は、Unity の Project ウィンドウの中でやる
  - エクスプローラーや Finder でやると、`.meta` ファイルとずれて、つながりが切れます。
- `.meta` ファイルは消さない。新しいファイルと一緒に必ずコミットする

## フォルダの分け方（例）

```
Game/Assets/
├─ Scenes/        シーン
│  └─ Test/       自分用のテストシーン
├─ Scripts/       プログラム
├─ Prefabs/       プレハブ
├─ Art/           絵・3D モデル・アニメーション
├─ Audio/         音楽・効果音
└─ ThirdParty/    アセットストアなど、外から入れた物
```

## 名前の付け方

| 何 | 決まり | 例 |
|---|---|---|
| ブランチ | `自分の名前/やること`（英語の小文字とハイフン） | `taro/player-jump` |
| コミットのメッセージ | 何をしたかを、日本語で 1 行 | 「敵がプレイヤーを追いかけるようにした」 |
| ファイル・フォルダ | 英語で書く。スペースや日本語は使わない | `PlayerController.cs`、`Title.unity` |
| C# のクラス | 大文字で始める。ファイル名と同じにする | `PlayerController` |

## 入れてはいけない物

- `Game/Library`・`Game/Temp`・`Game/Logs` などのフォルダ（`.gitignore` で自動的に外れます）
- 100MB より大きいファイル（GitHub に送れません）。50MB を超えそうな時は、先生に相談する
- パスワードや、住所・電話番号などの個人情報
- 使ってよいか確かめていない画像・音・フォント
  - 外から持ってきた素材は、入手先の URL と利用条件を Notion にメモしておきましょう。

## プルリクエストの決まり

- 1 つのプルリク = 1 つのタスク
- 仲間 1 人に Approve をもらってから、マージする
- マージしたら、ブランチを消す
- 2 日たっても見てもらえない時は、声をかける

## 困った時の決まり

- 1 人で 30 分悩んだら、仲間か先生に聞く
- 聞く時は、やったことと、出た画面のスクリーンショットを見せる
